# Dex5实机迁移：现象、证据与优化方向

## 当前阶段

主线为Isaac Oracle强化学习、Student蒸馏、硬件标定和受控回放。原记录已包含静态保持、受控轨迹执行和局部可见转动；实机连续转笔效果仍不稳定。Student仿真结果不能当作Student实机闭环部署结果。

## 迁移问题如何解释

|维度|已有记录或已观察现象|可以提出的解释与下一步|
|---|---|---|
|关节耦合|16个独立通道对应20维URDF目标，局部PIP/DIP响应比约0.29|需要匹配动作流形；辨识不同姿态和负载下的非线性，不能照搬另一仿真支线约0.829的假设|
|方向、偏置与迟滞|已有全范围方向扫描、分方向分段逆映射和局部修正记录|复核实际执行区间，保留往返分支，避免只用单姿态线性修正|
|控制时序|策略60Hz、指令链100Hz；局部起动14–31ms|同步动作保持、插值与延迟模型；任意放慢轨迹会改变接触动力学|
|增益与负载|历史回放发生过独立关节反馈瞬态，低增益静态保持可以通过|检查增益、预加载、负载与接触耦合；静态稳定不能证明动态回放稳定|
|物体与接触|记录包含更换约9.8mm直径笔及受控前缀验证|统一笔尺寸、质量和接触条件，分段定位失去支撑或接回失败的时刻|
|感知与评估|原始SDK速度出现过不合理尖峰，部分阶段没有力样本|使用已验证的位置差分；实机转角需要外部笔姿态信号或经校验的视频标注|

上述机制是有证据支持的候选瓶颈，尚未通过完整因果消融证明哪一项主导。不能把实机效果不佳全部归因于厂家或某个设置。

## 可以诚实呈现的工程价值

把仿真策略接到硬件上不是直接复制网络权重。项目已经覆盖关节映射、耦合约束、时序适配、受控回放、反馈诊断与阶段验收。当前局限是连续动态操作的稳定性，下一步应围绕仿真与负载下真实响应的一致性建立对照实验。

建议按“统一笔和控制参数 → 空手映射复核 → 静态负载保持 → 有限前缀回放 → 外部姿态评估 → 独立真实数据适配”推进。这里只描述后续路线，不授权新的带电回放，不改变已有硬件门槛。

## 视频与指标对应关系

1. MuJoCo视频是真实物理回放，含规划辅助和PPO收尾；用于解释动作与接触，不证明原Isaac学生策略完成整圈。
2. 152/197是原Isaac Student短角度测试结果，不是实机或整圈成功率。
3. 真机局部动作与标定结论来自原项目阶段记录；未新增或伪造实机视频、测量数据或成功率。
