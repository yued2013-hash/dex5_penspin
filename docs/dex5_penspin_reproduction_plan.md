# Dex5-PenSpin 复现任务书

> 目标不降级：在 Dex5 真机上实现笔状物体连续多圈稳定转笔。  
> 方法参考：《Lessons from Learning to Spin "Pens"》及其官方代码路线。  
> 当前日期：2026-07-08。

## 1. 最终目标

最终目标：

```text
Dex5 真机手内连续多圈稳定转笔。
```

更具体地说：

```text
Dex5 能在闭环反馈下控制笔状物体绕主轴连续旋转。
策略不只是 open-loop 播放动作，而是能根据手部状态和物体状态进行修正。
```

目标验收指标：

| 指标 | 初始验收 | 进阶验收 | 说明 |
|---|---:|---:|---|
| 连续旋转圈数 | >= 2 圈 | >= 5-10 圈 | 以笔主轴旋转角累计计算 |
| 单次成功率 | >= 50% | >= 80% | 固定初始化与固定物体条件下评估 |
| 物体保持 | 不掉落 | 多物体不掉落 | 掉落即失败 |
| 安全性 | 不触发关节/力/速度保护 | 长时间稳定 | 真机优先级最高 |
| 泛化 | 1 种笔状物体 | 2-3 种笔状物体 | 长度、重量、摩擦不同 |
| 记录完整性 | 视频 + 轨迹 + reward | 全量实验报告 | 可复盘、可对比 |

## 2. 参考论文路线

参考论文：

- Project: https://penspin.github.io/
- Paper: https://arxiv.org/abs/2407.18902
- PMLR: https://proceedings.mlr.press/v270/wang25j.html
- Code: https://github.com/HaozhiQi/penspin

论文核心路线：

```text
1. 在仿真中用 privileged information 训练 oracle policy
2. 用 oracle rollout 训练 student policy
3. 把 oracle 轨迹在真机上 open-loop replay，筛选成功真实轨迹
4. 用真实成功轨迹 fine-tune student policy
```

官方代码 README 中对应的四步：

```text
1. Learn an oracle policy with privileged information, point-clouds, and tactile sensor output with RL in simulation.
2. Learn a student policy using the rollout of the oracle policy, also in simulation.
3. Rollout trajectories generated by the oracle policy in a real robot, with initial state distribution matched.
4. Finetune the student policy with the real-world successful trajectories.
```

这条路线对 Dex5 的意义：

```text
仿真 RL 负责探索动态转笔技能
oracle policy 负责生成高质量轨迹
student policy 负责学习可部署的传感器输入策略
真机 open-loop replay 负责筛选真实可行轨迹
real fine-tuning 负责修正 sim-to-real gap
```

### 2.1 论文中需要优先理解的新概念

这些概念不是和你前面做过的 Pendulum、InvertedPendulum、Reacher 项目割裂的，而是把原来的标准 RL 流程升级到真实灵巧手任务。

**Oracle policy**

```text
oracle policy = 仿真里的“强老师”
```

它训练时可以使用真机部署时拿不到的信息，例如：

```text
pen pose
pen angular velocity
pen point cloud
fingertip position
binary tactile signals
object mass / friction / COM / scale
full simulator state
```

这类信息在论文里叫 privileged information。它的作用是让仿真 RL 更容易学出连续转笔这种高难度动态技能。

对 Dex5 的启发：

```text
Dex5 仿真 oracle 可以先大胆使用 pen 的完整状态。
不要一开始就要求 oracle 只能看真机可得观测。
oracle 的职责是产生高质量动作模式和轨迹，不是直接部署。
```

**Privileged information**

```text
privileged information = 训练时可用、部署时不可直接用的信息
```

例如仿真器天然知道笔的精确姿态和角速度，但 Dex5 真机控制器本身并不会发布这些量。

对 Dex5 的启发：

```text
仿真训练阶段：允许使用精确 pen pose / angular velocity / contact。
真机部署阶段：只能使用 qpos、dq、target_qpos、触觉/力，以及外部追踪得到的物体估计。
```

**Student / sensorimotor policy**

```text
student policy = 最终希望部署的策略
sensorimotor policy = 使用真实传感器输入做动作的策略
```

论文发现，oracle 不能直接部署，因为它依赖 privileged information；而直接把视觉/触觉策略从仿真迁移到真机，sim-to-real gap 太大。因此论文重点使用 proprioceptive policy，也就是主要依赖关节本体信息的策略。

对 Dex5 的启发：

```text
第一版 student 输入应优先使用 qpos、dq、target_qpos、last_action 的历史窗口。
触觉/力可以逐步加入。
视觉/物体状态先用于评估、筛选、reward，再谨慎加入闭环 policy。
```

**Policy distillation / BC**

论文里的 student pre-training 本质上和你之前做过的 BC 很接近：

```text
teacher / oracle rollout -> obs, action dataset -> student supervised learning
```

你之前的标准仿真项目是：

```text
PD 或 CEM expert -> demo data -> BC policy
```

论文路线变成：

```text
RL oracle expert -> high-fidelity trajectory dataset -> student policy
```

区别是 expert 更强，任务更难，数据不只是为了跑通 BC，而是为了后续真机 replay 和 real fine-tuning。

**High-fidelity trajectory dataset**

trajectory 不只是单步 transition，而是一整段可复现的动作序列：

```text
qpos_t
target_qpos_t
action_t
object_state_t
contact_t
success / failure label
video
```

论文强调高质量仿真轨迹有两个用途：

```text
1. 用于 student pre-training
2. 用于真机 open-loop replay，筛选真实成功轨迹
```

**Open-loop replay**

```text
open-loop replay = 不根据当前状态重新决策，只按时间播放一段轨迹
```

这一步在论文中非常关键。原因是转笔任务太动态，人类遥操作很难采集高质量示教。论文不是先找人遥操作，而是：

```text
仿真 oracle 生成动作序列
-> 真机按序播放
-> 成功的真实轨迹留下
-> 失败的丢弃或标注
```

对 Dex5 的启发：

```text
Dex5 第一批真机数据不一定来自人示教。
可以先来自仿真 oracle / scripted oracle 的 target_qpos replay。
但 replay 必须有安全限幅、急停和视频记录。
```

**Real-world fine-tuning**

论文里的 real fine-tuning 更接近：

```text
用真实成功轨迹继续监督训练 sensorimotor policy
```

它不是一开始就在真机上高噪声 online RL 探索。原因很现实：

```text
真机在线探索风险高
动态转笔失败代价高
sim-to-real gap 大
成功轨迹少但价值高
```

对 Dex5 的启发：

```text
先做 real successful trajectories -> supervised fine-tuning。
等 replay、追踪、安全层可靠后，再考虑小噪声 online RL。
```

### 2.2 与前置标准仿真项目的联系和区别

你之前做过的流程：

```text
Gymnasium / MuJoCo 标准环境
-> random baseline
-> scripted expert / CEM / PD expert
-> demo data
-> BC policy
-> TD3 fine-tuning
-> best checkpoint evaluation
```

论文路线对应为：

```text
Dex5/Allegro 灵巧手仿真
-> oracle RL
-> oracle trajectory dataset
-> student policy distillation / BC
-> real open-loop replay
-> real successful trajectory dataset
-> real-world fine-tuning
-> multi-object real evaluation
```

两者的核心联系：

```text
expert 仍然负责产生高质量行为
BC 仍然负责把 expert 行为压到 policy 里
evaluation 仍然要看 return / duration / success / videos
checkpoint 仍然要比较 best / final / baseline
```

主要区别：

| 维度 | 标准仿真项目 | PenSpin 论文路线 |
|---|---|---|
| 环境 | Pendulum / Reacher 等标准环境 | 灵巧手 + 笔状物体 + 动态接触 |
| expert 来源 | PD / CEM / 简单 scripted policy | 仿真 RL 训练出的 oracle policy |
| observation | 环境直接给低维状态 | oracle 用 privileged state，student 用可部署传感器 |
| 数据 | demo data 主要服务 BC | trajectory 同时服务 BC、replay、real fine-tuning |
| fine-tuning | 可在线 RL 探索 | 优先真实成功轨迹监督微调 |
| 风险 | 仿真失败无成本 | 真机有硬件、安全和数据成本 |
| 成功指标 | return / episode length | 旋转弧度、圈数、成功率、泛化物体 |

一句话总结：

```text
你之前学的是 RL/BC 的最小闭环。
论文路线是把这个闭环变成真实灵巧手可执行的 sim-to-real 数据闭环。
```

## 3. 本项目不降级但分阶段

目标不降级，但工程必须分阶段。分阶段不是降低目标，而是保证每一步都可验证。

总路线：

```text
Dex5-PenSpin MDP 定义
-> Dex5/pen 仿真环境
-> 仿真 oracle policy
-> oracle trajectory dataset
-> student policy distillation
-> 真机 open-loop replay
-> real successful trajectories
-> real fine-tuning
-> 多圈稳定评估
```

执行顺序原则：

```text
先仿真，后真机。
先 oracle / trajectory，再 replay / real fine-tuning。
相机、marker、手眼标定属于真机 replay 和评估阶段的准备项，不阻塞 M2/M3 的仿真启动。
```

当前已确认的真机感知条件：

```text
RGB-D 相机：奥比中光 355
笔身 marker：允许贴 marker / 颜色标 / AprilTag / ArUco
相机到 Dex5 手坐标系标定：暂无，需要在真机 replay 前补齐
```

## 4. Dex5-PenSpin MDP 初版

### 4.1 Observation

按优先级分为三层。

最小 proprioception：

```text
Dex5 joint position q
Dex5 joint velocity dq
last action
finger target qpos
```

物体状态：

```text
pen pose
pen axis direction
pen angular velocity
pen rotation phase around long axis
pen center position
pen endpoints position
```

接触/感知：

```text
fingertip contact state
force / tactile signal
camera depth / point cloud
object endpoint detection
```

初期建议：

```text
仿真 oracle 使用 privileged object state
student policy 优先使用 proprioception + 可获得的 object estimate
真机部署优先从 proprioception + 简化 object tracking 开始
```

### 4.1.1 Pen State 设计：补齐 pen pose / endpoints / angular velocity / rotation phase

论文中 oracle policy 使用笔的当前 pose、angular velocity 和 point cloud 等 privileged information；真实阶段的数据中保留 RGB、depth、point cloud 和 `obj_ends`。因此 Dex5-PenSpin 也需要把物体状态拆成两类：

```text
训练 oracle 用的真值物体状态
真机 replay / fine-tuning 用的估计物体状态
```

#### A. pen endpoints

定义：

```text
pen_endpoint_a: 笔一端的 3D 位置
pen_endpoint_b: 笔另一端的 3D 位置
pen_center = 0.5 * (pen_endpoint_a + pen_endpoint_b)
pen_axis = normalize(pen_endpoint_b - pen_endpoint_a)
```

论文对应：

```text
官方 real_data_full.h5 中有 obj_ends。
teacher_replay.py 后处理阶段会用 RGB-D/point cloud 得到 object ends。
```

Dex5 第一版建议：

```text
优先做 marker-based endpoint tracking。
使用奥比中光 355 作为外部 RGB-D 相机。
在笔两端贴颜色/AprilTag/ArUco/反光点，用外部相机估计两个端点。
```

原因：

```text
端点比完整 6D pose 更容易稳定估计。
只要两个端点稳定，就能得到 pen center、pen axis、掉落检测和大部分 success metric。
```

数据字段：

```text
obj_ends: [T, 2, 3]
pen_center: [T, 3]
pen_axis: [T, 3]
```

最低可用标准：

```text
每帧能输出两个端点的 3D 坐标。
遮挡时允许短时插值，但必须记录 tracking_valid。
```

#### B. pen pose

定义：

```text
pen_pose = [position, orientation]
position = pen_center
orientation = 由 pen_axis + 绕长轴相位组成的姿态
```

需要注意：

```text
只靠两个端点只能确定笔的长轴方向，不能完整确定“绕长轴自转相位”。
如果笔是完全对称圆柱，视觉上也很难看出绕长轴转了多少。
```

因此 Dex5 中 pen pose 分两层：

```text
pose_axis_only:
  pen_center + pen_axis
  用于掉落、倾斜、位置稳定、open-loop replay 筛选

pose_full:
  pen_center + pen_axis + rotation_phase
  用于精确计算连续多圈转笔
```

实现建议：

```text
仿真中使用 simulator ground-truth full pose。
真机第一版使用 endpoint-based axis pose。
真机进阶版在笔身贴非对称纹理/标记，恢复绕长轴 phase。
```

数据字段：

```text
object_pose_axis: [T, 6]      # center xyz + axis xyz
object_pose_full: [T, 7]      # center xyz + quaternion，可选
tracking_valid: [T]
```

#### C. pen angular velocity

定义：

```text
pen_angular_velocity = 笔的角速度向量
spin_velocity = dot(pen_angular_velocity, desired_spin_axis)
```

论文对应：

```text
oracle observation 中包含 pen angular velocity。
reward 主要鼓励笔绕目标轴持续旋转。
```

Dex5 实现分层：

```text
仿真 oracle:
  直接读取 simulator object angular velocity

真机 replay / evaluation:
  从连续帧 pen pose / endpoints / phase 估计

真机 student policy:
  初期不强依赖 angular velocity
  可作为 reward/evaluation 信号
  等追踪稳定后再加入 observation
```

如果只有端点，没有长轴相位：

```text
可以估计 pen_axis 的摆动角速度
但不能准确估计绕笔自身长轴的自转速度
```

因此连续多圈转笔要想评估准确，最终需要：

```text
非对称视觉标记
或高帧率相机 + 纹理追踪
或专门的物体 pose tracker
```

数据字段：

```text
object_angvel: [T, 3]
spin_velocity: [T]
```

#### D. rotation phase

定义：

```text
rotation_phase = 笔绕目标旋转轴的累计相位
rotation_progress_t = unwrap(rotation_phase_t - rotation_phase_{t-1})
rotation_rounds = abs(total_rotation_progress) / (2*pi)
```

这里要区分两个容易混淆的 phase：

```text
finger-gaiting phase:
  手指接触/换指完成了一个循环

object spin phase:
  笔本体绕某个轴累计转了多少角度
```

论文真实评估中使用 rotation radians 和 success rate。它把至少 180 度旋转作为 success 判断之一，并指出这通常对应一圈 finger gaiting。我们的目标更高，是 Dex5 连续多圈稳定转笔，因此需要记录累计 rotation phase。

Dex5 第一版可执行方案：

```text
1. 在笔身贴一个非对称视觉标记，保证绕长轴旋转时可见相位变化。
2. 用相机估计每帧 marker 方向。
3. 将角度序列 unwrap，得到连续 rotation_phase。
4. 根据累计角度计算 rounds。
```

如果第一阶段暂时没有稳定 phase tracking：

```text
open-loop replay 阶段可先用视频人工标注 success/failure。
但进入 closed-loop policy 和多圈验收前，必须补齐自动 phase/rounds 估计。
```

数据字段：

```text
rotation_phase: [T]
rotation_progress: [T]
rotation_rounds: scalar
success_rotation_threshold_rad: 初始 pi，进阶 4*pi 到 10*pi+
```

#### E. 推荐落地顺序

不要一开始追求完整 6D pose 和完美角速度。按论文路线，先让这些状态服务于数据筛选和评估，再逐步进入 policy observation。

```text
M2 仿真阶段:
  使用 simulator ground truth:
    pen pose
    pen endpoints
    pen angular velocity
    rotation phase

M5 真机 replay 初期:
  使用 RGB 视频 + 人工/半自动标注:
    success
    failure_reason
    rough rotation rounds

M5 真机 replay 进阶:
  使用 marker-based endpoints:
    pen_center
    pen_axis
    drop detection
    object_out_of_workspace

M6 real fine-tuning:
  数据中保留 object estimate
  policy 初期仍以 proprioception 为主
  object estimate 先用于筛选、评估和 reward

M7 closed-loop multi-round:
  加入稳定 phase tracking
  允许 policy 使用 object estimate 或其低维滤波结果
```

### 4.2 Action

候选动作空间：

```text
joint position delta
joint velocity target
low-level target qpos
```

建议初版：

```text
action = delta target qpos
```

理由：

```text
比直接力矩更安全
容易加入限幅
适合真机 replay 和 policy 执行
```

动作约束：

```text
单步 delta 限幅
关节位置限幅
关节速度限幅
动作平滑惩罚
安全 filter 二次裁剪
```

### 4.3 Reward

核心 reward：

```text
rotation_reward：笔绕长轴旋转速度 / 累计旋转角
```

稳定 reward：

```text
hold_reward：笔没有掉落
pose_reward：笔轴姿态不过度倾斜
center_reward：笔中心保持在手内合理区域
contact_reward：关键手指保持有效接触
```

安全/正则：

```text
action_smooth_penalty
joint_limit_penalty
velocity_penalty
object_drop_penalty
large_tilt_penalty
```

初版 reward 结构：

```text
reward =
  w_rot * rotation_progress
+ w_alive * alive
+ w_contact * contact_stability
- w_drop * drop
- w_tilt * excessive_tilt
- w_action * action_norm
- w_smooth * action_delta
```

### 4.4 Done / Reset

terminated：

```text
pen dropped
pen center leaves hand workspace
pen tilt exceeds threshold
joint safety violation
force / velocity safety violation
manual emergency stop
```

truncated：

```text
episode reaches max steps
```

reset：

```text
hand returns to canonical grasp
pen initialized to known pose
sensor streams synchronized
controller enters ready state
```

## 5. 工程模块划分

### 5.1 Simulation

目录：

```text
sim/
```

目标：

```text
建立 Dex5 + pen-like object 仿真环境
定义 observation/action/reward/done
训练 oracle policy
导出 oracle trajectories
```

关键任务：

```text
导入 Dex5 URDF / MJCF
建立 pen object 模型
设置接触参数、摩擦、质量、惯量
实现 reset distribution
实现 reward logging
实现 policy rollout visualization
```

### 5.2 Student Policy

目标：

```text
用 oracle rollout 训练 student policy
```

输入：

```text
student observation
```

输出：

```text
Dex5 action
```

训练方式：

```text
behavior cloning
DAgger-like correction 可选
offline imitation pretraining
```

### 5.3 Real Replay

目录：

```text
real/
```

目标：

```text
把仿真/策略轨迹转换成 Dex5 真机可执行 target qpos 序列
执行 open-loop replay
记录成功/失败轨迹
```

必须记录：

```text
timestamp
qpos
dq
action
target_qpos
sensor state
object pose estimate
success flag
video path
safety event
```

### 5.4 Real Fine-Tuning

目标：

```text
使用真实成功轨迹微调 student policy
```

优先级：

```text
先做 real trajectory supervised fine-tuning
再考虑小噪声 online RL
```

真机 online RL 必须具备：

```text
safety filter
emergency stop
action clamp
rollback checkpoint
best checkpoint
low exploration noise
human monitoring
```

## 6. 数据格式设计

建议统一使用 HDF5 或 NPZ。初期可以 NPZ，正式数据建议 HDF5。

一个 trajectory 至少包含：

```text
trajectory_id
source: sim_oracle / sim_student / real_replay / real_finetune
success: bool
failure_reason
timestamps: [T]
qpos: [T, dof]
dq: [T, dof]
```

## 7. 训练阶段设计

### Stage 1: Oracle Policy in Simulation

目标：

```text
训练一个能在仿真中连续转笔的 oracle policy
```

oracle 可以使用 privileged information：

```text
pen pose
pen velocity
contact state
full simulator state
```

候选算法：

```text
PPO
SAC
TD3
IsaacGym/Hora style RL
```

本阶段重点：

```text
探索动态技能
形成可用动作模式
不要求直接 sim-to-real
```

### Stage 2: Oracle Dataset

目标：

```text
用 oracle 生成高质量转笔轨迹
```

筛选标准：

```text
连续旋转角度
不掉落
动作不过大
接触稳定
trajectory length 足够
```

输出：

```text
sim_oracle_dataset.h5
```

### Stage 3: Student Policy

目标：

```text
训练一个可部署的 student policy
```

student 不应依赖不可获得的 privileged state。

训练：

```text
BC from oracle trajectories
可能加入 noise / domain randomization / observation dropout
```

### Stage 4: Real Open-Loop Replay

目标：

```text
将 oracle/student 轨迹转为真机 target qpos replay
```

关键：

```text
初始状态匹配
动作频率匹配
安全限幅
失败立即停止
成功轨迹保留
失败轨迹标注
```

### Stage 5: Real Fine-Tuning

目标：

```text
用少量真实成功轨迹适配真实动力学
```

优先方案：

```text
real successful trajectories -> supervised fine-tuning
```

进阶方案：

```text
online RL with safety constraints
```

### M2.2.5: Hand / Pen Initial Pose Decision

结论：

```text
如果目标是复现《Lessons from Learning to Spin "Pens"》中的 fingergaiting 和 continuous spinning，
Dex5 可以采用论文中接近 palm-up / palm-supported 的 reset。
关键不是手掌必须斜立，而是笔不能只像静态物体一样躺在掌心。

平卧式 reset 可以保留为：
  1. MuJoCo 导入测试
  2. 接触/摩擦/可视化调试
  3. 数据结构和脚本验证

论文复现主线应转向：
  palm-up / palm-supported
  pen 横跨多指
  pen 由掌面、指尖、指节共同支撑
  指尖/指节能够主动改变接触点并推动旋转
```

原因：

```text
论文中的技能重点是 emergent fingergaiting：
  笔在多指之间通过接触切换和指间步态持续旋转。

如果笔只是被动平放在掌面上：
  任务会退化成防止物体滑落/滚动；
  policy 容易学到托住而不是转笔；
  rotation_phase 和 finger-gaiting 的关系会变弱；
  后续 sim-to-real replay 也不接近论文中的多指步态机制。
```

Dex5 推荐 reset 方向：

```text
paper-like palm-up reset:
  掌面可接近水平或轻微倾斜
  笔轴横跨 index/middle/ring 附近
  笔与多指发生接触，而不是只和掌面接触
  拇指从对侧提供约束
  手指后续动作能够改变接触点，形成 finger gait
```

```text
  证明真实 Dex5 URDF + pen + contact proxy 能稳定仿真。

它的限制：
  更像被动支撑，不是论文式主动夹持。
  不能作为最终 oracle RL 的主要 reset distribution。
```

### M2.7: Tripod Fingertip Support Reset

### M2.10: Directed Micro-Gait

```text

  1. 不再只看 rotation_phase_abs，而是显式计算 directed phase progress。
  2. 增加 phase_direction，搜索顺时针/逆时针哪个方向更适合当前 reset。
  3. 把 finger motion 改成更像 ratchet 的 directed micro-gait：
       close phase 负责推动；
       return phase 尽量弱一些，减少反向抵消；
       roll_scale 给指根侧向微小滚动补偿。
```

M2.10 里几个新指标的含义：

```text
final_progress:
  按指定 phase_direction 计算出来的最终相位推进量。
  越大表示笔整体更朝目标方向转。

positive_progress:
  所有正向相位增量之和。

negative_progress:
  所有反向回退相位增量之和。
  这个值越小，说明相位越少来回摆。

monotonic_ratio:
  positive_progress / (positive_progress + negative_progress)
  越接近 1，说明相位越单调。

max_drawdown:
  从历史最大 directed phase 回落的最大幅度。
  它能衡量“转过去以后又退回来多少”。
```

## 13.3 M3.2.13 Contact-Gated Directed Relay

本阶段把相位推进改成接触门控指标：

```text
有效相位推进 = 正向相位增量 * contact gate weight
```

其中 contact gate 分为：

```text
exact:
  目标接触组合全部出现。

near:
  3 指及以上组合允许缺 1 个目标接触；
  2 指组合必须两个都在。

support:
  至少 2 个目标手指接触。

active_wrong / lost:
  不允许计入 oracle progress。
```

## 13.4 M3.2.14 P1 Stable Reset Tuning

本阶段先回答一个更基础的问题：

```text
在进入 P1->P2 相位接力前，P1 初始化动作本身能不能稳定？
```

结论：

```text

thumb 在静态 reset 中强行加入时，会和 ring/middle 支撑竞争；
更合理的设计是：
  P1 reset 先保证三指托住笔；
  随后用 contact-conditioned controller 主动加入 thumb light clamp。
```

```text
1. 保持 Manus 采集手势观感，不做大幅手势重构。
2. 优先微调笔的 x / y / z / yaw / axis_z。
3. 允许手指关节小范围补偿，但限制 q_delta_max。
4. 用 normal servo，而不是 hard-hold，验证 reset 是否真实可保持。
5. 评分不只看 survival，还看 index/middle/ring/thumb contact ratio。
```

本轮尝试了三类结果：

```text
第一轮：thumb/ring/index 稳，但 middle 缺失。
第二轮：index/middle/ring 稳，但 thumb 缺失。
第三轮：从第二轮三指稳定 seed 出发局部 refine，得到更小手势改动的三指稳定 reset。
```

### 13.4.1 Thumb-Support Alternate Reset

根据可视化观察，三指托架版本虽然统计上稳定，但视觉上容易显得更偏 ring/pinky 侧支撑。
因此额外导出了一个 thumb-support 版本，作为后续“拇指轻托/轻夹”调试起点。

文件：

```text
dex5_penspin/reports/manus_mujoco_presets/p1_thumb_support_settled_balance_m3_2_14j/P1_thumb_support_settled_balanced_seed.json
```

复现脚本：

```text
dex5_penspin/sim/select_m3_2_14_thumb_support_reset.py
```

说明：

```text
早先的 p1_thumb_support_reset_m3_2_14d 来自 rank14，
短时看似稳定，但 viewer 中启动后会逐渐退化为 thumb-only / lost contact。
因此 14d 不再作为推荐 reset。

当前 viewer 推荐使用 p1_thumb_support_settled_balance_m3_2_14j。
它不是继续盲目加大力，而是把 reset 直接放到 extra-strong 版本 settle 后的平衡点。

它沿用较强的手指 position servo：

  kp = 1500, kv = 75

含义是：
  1. 手指有足够刚度；
  2. 笔初始位姿已经在 thumb/index/middle 的平衡位置；
  3. 按 SPACE 后不再经历明显滑落/滚落的 settling transient。
```

```text

near_ratio = 1.000
lost_ratio = 0.000
index_ratio = 1.000
middle_ratio = 1.000
thumb_ratio = 1.000
max_xy_drift ≈ 0.00020 m
max_3d_drift ≈ 0.00021 m

```

说明：

```text
14e/rank23：接触还在，但会长期缓慢下沉，viewer 中肉眼像掉落。
14f/rank20：高度更好，但用户观察仍希望“手指更发力”。

14j settled balance：保存 settle 后的平衡点，目前是最适合 viewer 观察“不掉落”的 thumb-support reset。
```

解释：

```text
这个版本是 thumb / index / middle 支撑，
更符合“大拇指托住”的调试直觉。

代价是：
  ring 基本退出；
  它不是四指 canonical grasp；
  因此它更适合作为 thumb-support 可视化和 P1->P2 light-clamp 起点，
  不一定替代最稳的三指托架 reset。
```

viewer 观察时，运行后终端应稳定显示：

```text
contacts=['index', 'middle', 'thumb']
```
