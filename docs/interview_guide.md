# 面试展示：Dex5灵巧操作与Sim-to-Real

简历用语见[可直接使用的项目描述](resume_project.md)，数据扩展目标见[扩展计划](data_scaling_plan.md)。

## 90秒开场

“我做的是一个以Isaac Lab为训练主平台的Dex5灵巧操作与Sim-to-Real项目，包含Oracle强化学习、Student策略蒸馏、硬件适配以及动作诊断与可视化四个模块，重点处理耦合关节下的控制约束与仿真实机响应差异。

项目已有的Student短角度仿真评估达到152/197次严格成功，184/197次达到30度实际姿态转动。真机阶段完成了标定、受控回放和局部动作验证，但连续转笔还不稳定。目前主要排查关节耦合、增益、负载响应及仿真实机时序差异；我会把测到的现象和待验证的机制分开说明。”

## 5分钟演示顺序

1. 先用架构图讲Oracle如何产生数据、Student为什么需要可部署观测。
2. 展示Student的152/197短角度测试及source隔离，说明不是整圈或实机成功率。
3. 播放项目动作诊断模块的视频，说明“这里展示转动、换位与接回过程，采用规划辅助的物理回放”。如被问运行器，准确说明该诊断模块使用MuJoCo，训练主平台是Isaac Lab。
4. 讲真机耦合、映射、增益与时序调试，展示哪些问题已有测量、哪些仍需消融。
5. 总结迁移尚未稳定的原因候选和下一步验证方案；新增残差PPO仅在被问到后作为补充探索。

## 工程贡献的表达

- 搭建Dex5笔状物体操作的仿真学习、策略蒸馏与受控真机验证流程。
- 设计姿态、接触和保持联合评估，排查只积分角速度产生的“假转动”。
- 对接20维URDF目标与16独立控制通道，处理关节耦合、方向偏置、迟滞和控制时序。
- 建立数据来源隔离、阶段校验、实验溯源与可视化展示。

说清实际承担的工作，不把公共算法当原创，也不将历史报告描述成本轮重新测得。

## 常见追问

**视频是不是RL学出来的？** 当前整圈视频是补充MuJoCo规划辅助回放，含PPO收尾；原项目Student的RL→BC验证是另一条Isaac短角度任务证据，二者分别标注。

**真机为什么不如仿真？** 目前连续转笔不稳定。已有耦合、控制时序和负载瞬态的测量，支持模型与执行条件不一致的解释；尚未证明单一设置是唯一原因。

**是不是Dex5硬件不行？** 不能这样下结论。已有静态与局部动作验证，动态连续操作仍受控制适配和接触裕量影响，需要受控对照来定位瓶颈。

**152/197说明什么？** 它是短角度Student仿真严格成功数，197个测试episode来自20个来源；不能外推到实机、整圈或197个独立来源。

**是否已经实机自主闭环？** 没有完成Student实机自主闭环认证。当前是真机标定、受控回放和局部动作验证。

**下一步怎么优化？** 先统一笔与执行条件、复核负载下耦合和时延，再做有限前缀与姿态评估，最后在独立阶段考虑真实数据适配。

**有哪些缺陷？** 实机连续性与泛化不足、部分接触/力数据不完备、补充MuJoCo存在几何质量和跨平台延续限制。详细证据见[迁移分析](sim2real_case_study.md)和[补充实验边界](results_and_limits.md)。

## 统一项目的一句话定位

基于Isaac Lab构建Dex5灵巧操作的强化学习与策略蒸馏流程，完成硬件适配、受控迁移验证和动作诊断工具建设，持续优化耦合关节与接触切换引起的执行差异。

引擎是实现细节，训练、蒸馏、硬件与诊断是同一个项目的模块；被问实现与证据时保留准确来源。
